## 3. Тест-кейсы

### TC-01. Открытие главной страницы

**Предусловие:** сервер запущен, тестовая база инициализирована.

**Шаги:**

1. Отправить `GET /`.
2. Проверить HTTP-статус и содержимое ответа.

**Ожидаемый результат:** сервер возвращает статус `200`, HTML содержит название `VoxSekai`.

**Фактический результат:** получен статус `200`, название найдено в HTML.

**Статус:** пройден.

### TC-02. Отображение трека в каталоге

**Предусловие:** в тестовой SQLite-базе есть трек «Отчётный трек».

**Шаги:**

1. Отправить `GET /catalog`.
2. Проверить заголовок страницы.
3. Найти тестовый трек в HTML.

**Ожидаемый результат:** страница отвечает со статусом `200`, содержит заголовок «Каталог музыки» и тестовый трек.

**Фактический результат:** каталог открыт, оба элемента присутствуют.

**Статус:** пройден.

### TC-03. Открытие страницы существующего трека

**Предусловие:** в базе есть трек с идентификатором `report-track`.

**Шаги:**

1. Отправить `GET /track/report-track`.
2. Проверить статус и данные трека.

**Ожидаемый результат:** статус `200`; страница содержит название трека и имя исполнителя.

**Фактический результат:** отображены «Отчётный трек» и «Тестовый исполнитель».

**Статус:** пройден.

### TC-04. Обработка неизвестного адреса

**Предусловие:** сервер запущен.

**Шаги:**

1. Отправить `GET /route-that-does-not-exist`.
2. Проверить HTTP-статус и текст страницы.

**Ожидаемый результат:** статус `404`, отображается страница «Страница не найдена».

**Фактический результат:** сервер вернул корректную страницу со статусом `404`.

**Статус:** пройден.

### TC-05. Защита страницы профиля от гостя

**Предусловие:** запрос выполняется без пользовательской сессии.

**Шаги:**

1. Отправить `GET /profile` без cookie.
2. Проверить перенаправление.

**Ожидаемый результат:** статус `302`, переход на `/login?next=%2Fprofile`.

**Фактический результат:** получено ожидаемое перенаправление.

**Статус:** пройден.

### TC-06. Регистрация нового пользователя

**Предусловие:** пользователя `report_user` ещё нет в базе.

**Шаги:**

1. Отправить `POST /register` с корректными именем, e-mail и паролем.
2. Проверить перенаправление и cookie сессии.
3. Проверить появление пользователя в SQLite.

**Ожидаемый результат:** статус `302`, переход на `/profile`, выдана cookie `connect.sid`, пользователь сохранён.

**Фактический результат:** все условия выполнены, в базе создана одна запись пользователя.

**Статус:** пройден.

### TC-07. Запрет повторного имени пользователя

**Предусловие:** пользователь `report_user` уже зарегистрирован.

**Шаги:**

1. Повторно отправить `POST /register` с именем `report_user`.
2. Проверить статус и сообщение об ошибке.

**Ожидаемый результат:** статус `400`, сообщение «Пользователь с таким именем уже существует».

**Фактический результат:** регистрация отклонена с ожидаемым сообщением.

**Статус:** пройден.

### TC-08. Выход пользователя из аккаунта

**Предусловие:** пользователь авторизован, имеется cookie сессии.

**Шаги:**

1. Отправить `POST /logout` с cookie пользователя.
2. Проверить перенаправление и удаление cookie.

**Ожидаемый результат:** статус `302`, переход на `/`, cookie `connect.sid` очищена.

**Фактический результат:** выполнено перенаправление, сервер отправил очищающую cookie.

**Статус:** пройден.

### TC-09. Вход с неверным паролем

**Предусловие:** пользователь `report_user` зарегистрирован.

**Шаги:**

1. Отправить `POST /login` с корректным e-mail и неверным паролем.
2. Проверить статус и сообщение.

**Ожидаемый результат:** статус `400`, сообщение «Неверный логин или пароль».

**Фактический результат:** доступ не предоставлен, показано ожидаемое сообщение.

**Статус:** пройден.

### TC-10. Вход пользователя по e-mail

**Предусловие:** пользователь `report_user` зарегистрирован и вышел из аккаунта.

**Шаги:**

1. Отправить `POST /login` с e-mail и правильным паролем.
2. Проверить ответ и cookie.

**Ожидаемый результат:** статус `302`, переход на `/`, выдана новая cookie `connect.sid`.

**Фактический результат:** пользователь успешно вошёл по e-mail, сессия создана.

**Статус:** пройден.

### TC-11. Открытие профиля авторизованным пользователем

**Предусловие:** имеется действующая сессия пользователя `report_user`.

**Шаги:**

1. Отправить `GET /profile` с cookie пользователя.
2. Проверить статус и отображаемое имя.

**Ожидаемый результат:** статус `200`, HTML содержит `report_user`.

**Фактический результат:** профиль открыт, имя пользователя отображается.

**Статус:** пройден.

### TC-12. Запрет оценки трека гостем

**Предусловие:** тестовый трек существует, пользователь не авторизован.

**Шаги:**

1. Отправить `POST /track/report-track/rate` со значением `5` без cookie.
2. Проверить перенаправление.

**Ожидаемый результат:** статус `302`, переход на вход с возвратом к странице трека.

**Фактический результат:** получен переход на `/login?next=%2Ftrack%2Freport-track`.

**Статус:** пройден.

### TC-13. Сохранение оценки авторизованного пользователя

**Предусловие:** пользователь авторизован, тестовый трек существует.

**Шаги:**

1. Отправить `POST /track/report-track/rate` со значением `5` и cookie пользователя.
2. Проверить перенаправление.
3. Прочитать оценку из таблицы `track_ratings`.

**Ожидаемый результат:** переход на `/track/report-track#rating`, в базе сохранена оценка `5`.

**Фактический результат:** перенаправление выполнено, значение `5` найдено в SQLite.

**Статус:** пройден.

### TC-14. Запрет входа обычного пользователя в админ-панель

**Предусловие:** пользователь `report_user` имеет роль `user`.

**Шаги:**

1. Отправить `POST /admin/login` с правильными данными обычного пользователя.
2. Проверить ответ и сообщение.

**Ожидаемый результат:** административная сессия не создаётся, отображается сообщение об отсутствии прав.

**Фактический результат:** показано сообщение «Этому аккаунту нельзя входить в админпанель».

**Статус:** пройден.

### TC-15. Вход администратора и открытие дашборда

**Предусловие:** в тестовой базе автоматически создан администратор.

**Шаги:**

1. Отправить `POST /admin/login` с корректными данными администратора.
2. Проверить перенаправление и cookie сессии.
3. Отправить `GET /admin` с полученной cookie.
4. Проверить элементы дашборда.

**Ожидаемый результат:** вход возвращает статус `302` и переход на `/admin`; дашборд отвечает со статусом `200` и содержит разделы «Треки» и «Пользователи».

**Фактический результат:** администратор вошёл, дашборд и его основные разделы доступны.

**Статус:** пройден.

## 4. Заключение

Все 15 запланированных тест-кейсов пройдены. В проверенном объёме блокирующих и функциональных дефектов не обнаружено.

Прогон покрывает серверные маршруты и работу с SQLite. В него не входят визуальная проверка адаптивной верстки, воспроизведение реального аудиофайла, загрузка медиа, доступность интерфейса и сценарии с `localStorage`. Для этих областей требуется отдельное браузерное тестирование.
